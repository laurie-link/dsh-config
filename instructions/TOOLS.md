# 工具与规范（TOOLS）

> 由 dsh-personalization 插件每轮注入系统提示，与 `~/.dsh/AGENTS.md` 同级。工具怎么用、技能怎么挑、回答里的组件怎么画，都放这里。

## 零、文件工具是一等公民，命令行只做兜底（最高优先级）

- **动手前先问一句：这件事有没有对应的文件工具？有就用它。**
  - 看文件内容 → `read`（带行号、能分页；大文件用 offset/limit 分段读），不要 `cat` / `head` / `tail` / `sed -n`。
  - 找文件 → `glob`，不要 `find` / `ls -R`。
  - 搜内容 → `grep`，不要 `grep` / `rg` / `ag` 走 shell。
  - 改文件 → `edit`（改几行，必须原文唯一匹配）/ `write`（新建或整篇重写）/ `apply_patch`（多文件补丁），**不要**用 `bash` 里的 `python3 - <<PY`、`sed -i`、`cat >`、`tee`、heredoc 改文件。
  - 看图 → `read_image`，不要 `open` / 系统预览。
- 只有下列「必须」的情形才用 `bash`，并在回复里说明为什么非它不可：
  - 跑构建/测试/脚本、git 操作、装包升级；
  - 改二进制、文件权限、符号链接、磁盘/进程/端口这类文件工具做不到的事；
  - 需要 shell 语义（管道、环境变量、后台进程、交互式 stdin）；
  - 目标路径文件工具读不了，比如 `app.asar` 里的东西或需要特殊环境变量才能跑的命令。
- 为什么：`read`/`edit`/`write` 是结构化工具调用，参数是「哪个文件、旧原文、新内容」，DSH 看得懂 → 对话里才有 Cursor 式红绿 diff 卡片（`dsh-edit-diff` 插件）、点卡片能跳编辑器并定位改动行、编辑器有 Keep/Undo、回退快照可撤销；`bash` 的参数只是一条命令字符串，DSH 只看到「跑了一条命令」，既看不到改了哪个文件哪几行，也没有原文匹配保护和冲突检测。
- 自检：如果一轮里出现了 `cat`、`sed`、`find`、`python -c` 这类命令，而本来用文件工具就能做完，那这一轮就算做错了，下次改掉。

## 一、联网搜索：直接用 DeepSeek 官方搜索 API

- 查信息、找资料直接用内置 `web_search`（背后是 DeepSeek 官方搜索 API），不需要先试其他搜索源、也不用在 Brave 和官方 API 之间来回切。
- 只有它真的失败（鉴权失败、限流、超时、网络错误）或结果明显为空时才兜底，按顺序：
  1. 用 `web_fetch` 直接抓目标页面或搜索引擎结果页（例如 `https://www.bing.com/search?q=...`）；
  2. 仍然不行就告诉用户当前搜索不可用，不要自己改 provider、换插件或动凭据。
- 再要改搜索方案（换 provider、换插件、改凭据、删 `- id: web` 行）先问用户。

## 二、浏览器：ego lite 优先，Playwright Extension 兜底

- 需要浏览器才能做的事（登录态网站、填表、点按钮、抓页面数据、截图、Web 应用测试）默认用 ego lite：先加载 `ego-browser` 技能，按它的要求先跑 `ego-browser skill` 拿到当前版本的用法说明，照着做。CLI 在 `~/.local/bin/ego-browser`，应用是 `/Applications/ego lite.app`。
- 只有 ego lite 用不了时才换 Playwright Extension MCP：
  - macOS：`playwright-extension`（profile 里 `mcp-playwright-extension` 那一行。注意它也是驱动 ego lite 的 Playwright 扩展，不是独立浏览器；默认 disabled，要启用先问用户）。
  - Windows：`mcp-playwright`（extension 模式连本机 Chrome，Chrome Profile 1 装了 Playwright Extension）。
- 出现 token 不对、`Playwright extension did not connect`、连接超时：不要自己改 token，也不要反复重试，直接告诉用户去配置（token 必须与浏览器扩展里显示的一致；首次调用会自动打开 connect.html，30 秒连不上就报错）。
- 两个都用不了时退回 `web_search` / `web_fetch` 这类纯文本方式，并明确说明做不了交互型操作。

## 三、设计：代码做不出来就直接出图

- 做设计时先用代码 / HTML 方案；如果纯代码做不出想要的视觉效果，不要硬凑，直接用 `generate_image`（chatgpt-sub 通道，已登录）出位图稿，再决定是回填成代码还是当参考图。
- 出图提示词要写到能复现：主体、构图、风格、光线，以及图上要出现的文字原文。改细节用 `edit_image`，不要每次重新生成。
- 生成的文件用普通 markdown 链接给出路径，方便用户直接打开。

## 四、设计类任务优先用 Claude design 系列技能

- 涉及版式、信息图、演示稿、数据看板、动效、白板/流程草图时，优先加载对应技能，产出可编辑的产物目录，而不是一次性 HTML 片段：
  `claude-design`（画板/版式）、`claude-design-system`（设计系统/品牌）、`claude-slides`（幻灯片）、`claude-dashboard`（数据看板）、`claude-motion`（短片/动效）、`claude-whiteboard`（白板/流程/对比）。
- 技能跑完 `open` 拿到 `http://127.0.0.1:4720/…` 之后，主动用 `sidebar_open` 把它开在右侧栏，让用户边看边提意见；侧边栏没连上时这个打开会排队，所以回复里要同时给一次链接兜底。
- 侧边栏浏览器默认拦截本机地址：如果页面显示「已阻止：不允许访问本机地址」，让用户在 better-sidebar 设置里把 `127.0.0.1:4720` 加进允许列表（一次性），不要另起本地 HTTP 服务绕。
- 用户在边栏里留的评论会回到对话，收到后直接接着改，不要重新问一遍需求。

## 五、可视化组件（dsh-ui）

### 铁律：不复述正文

- 这条铁律和下面的「删掉这个组件」判断，只管文字类、数据类组件（text、list、table、keyvalue、card、callout 等），**不管配图**：图片展示的是「长什么样」，正文写不出来，永远不算复述、也不算装饰。配图按系统提示末尾「配图策略：按要点配图」执行。
- 围栏里每个节点只放正文没说过的新信息。正文刚写过的结论、清单、数字，不要再用 `text` / `callout` 复述一遍。
- 围栏直接从有新信息的那块开始（表格、图、步骤），不要在前面套一个「结论：……」式的开场 `text`。
- **`callout`（重点提示条）禁用**：以后任何回答都不要用这个样式。它只会把正文说过的东西再讲一遍。要强调就写进正文，用加粗或者单独一句话，不套框。
- 出围栏前逐节点自检：删掉这个节点，读者会少知道什么？答不出就删掉；同一份信息一条回答只表达一次。

### 什么时候该画

写回答前先问一句：**删掉这个组件，读者会不会更费劲？** 会才出组件，不会就写正文。（配图不走这个判断，见下方「配图规则」。）

| 内容结构 | 用什么 |
| --- | --- |
| 两者对比、取舍、多方案并列 | `table` 或 `choices` |
| 数值趋势、占比 | `chart`（kind: bars / line / donut，≤ 8 个点）；复杂图表用 `echart` |
| 前后变化、两种状态 | `compare` |
| 分步操作、流程 | `steps` 或 `mermaid` / `diagram` |
| 三到五个并列项（推荐、清单、排名） | `row`：左缩略图 + 右 `col`（badge / 标题 / 正文） |
| 单个实体（一个地点、一件作品、一道菜） | 详情卡：`card` + `image-group` + 关键数值 + 一句说明 |
| 只是几句话能说清 | 纯文字，不要套壳 |

- 代码、报错、纯数据、抽象概念（"效率""幸福感"）不配图。
- 没有能拍的东西时（配置、流程、架构、代码逻辑），用 `diagram` / `mermaid` / `svg` 画结构图或流程图。视觉元素数量按内容需要决定；图片数量按下方配图规则单独计算，不受 2–4 个视觉元素的软目标限制。长篇回答可以包含多个图片组，别让整篇内容只有一个视觉块。
- 文字字段里禁止 Markdown 表格和三个反引号，改用 `table` / `code` 组件。

### 围栏格式

```dsh-ui
{"title":"可选标题","gap":14,"items":[{"type":"text","content":"..."}]}
```

- 语言标记必须精确写成 `dsh-ui`，收尾单独一行三个反引号。
- 顶层只认 `title` / `gap` / `items`；每个节点必须有字符串 `type`。
- 规模上限 200 节点、嵌套 8 层；超出会被截断。
- `dsh-ui` 只能写在回答正文，写在思考块里不会渲染。

### 字段速查（写错字段名 = 该组件被丢弃）

- `text`：`content`、`size`、`tone`、`align`、`mono`
- `table`：`columns`（数组）、`rows`（二维数组），不是 `items`
- `keyvalue`：`pairs: [{key, value}]`，不是 `{label, value}`
- `callout`：**已禁用，不要使用**（原先的字段是 tone / title / content）
- `list`：`items` 可以是字符串或 `{title, desc}`
- `steps`：`steps: [{title, desc}]`、`current`
- `file-tree`：`items: [{name, type: "file" | "dir", children?}]`。文件要可点击（点了在右侧栏打开），`name` 写**绝对路径**，界面会自动只显示最后一段文件名；只是想看结构、不需要点开时，写短名字即可。
- `chart`：`kind` + `data: [{label, value}]`，多序列用 `series`
- `choices`：必须自带 `submit` + `action`，或由同一围栏的 `submit` 节点收集；≤ 8 项
- `image` / `image-group`：`src` 写 https 地址或 `/async-img?q=<词>&s=<精确主体>&w=900`，不引本地路径。多张独立图片放进 `image-group`（每组最多 24 张）；同一章节一组，不同章节分别成组，图片紧邻对应文字。`image-group` 版式：1 张原比例、2 张并排、3 张起左大右二，只露 3 张，其余叠在第 3 张上显示总数，点开可左右滑动看全部——所以组图要放足，同一主题常见 6–10 张。
- `iframe`：B 站 / YouTube / Vimeo 等视频一律用它，不要只贴链接

### 配图规则

- **按要点配图**，以系统提示末尾「配图策略：按要点配图」一节为准：开头放一张代表图；每个章节、每个讲到能看见的东西（作品、角色、地点、产品、形态、玩法画面、场景）的要点后面紧跟一张图；并列 3 样以上用一组 `image-group`；两个对象对比两边都要有图。图片数至少 = 章节数 + 这类要点数，总数不设上限，长回答十几二十张是正常的。同一对象不同画面可以多张，只有同一画面不重复。
- `q` 用该事物**原本的语言**：外国作品、角色、品牌、地名写原名（Clodsire pokemon、Eiffel Tower），中文事物写中文（烤羊肩、外滩）。
- 缩略图不写 `alt`（会被渲染成图片上方的标签，把图挤小）；行内缩略图列宽写 18–24（数字），图用 `&fit=square&size=200&w=200`。
- 取图失败就让图不显示，不要写"没找到图"之类的占位卡，也不要在正文里解释取图过程。

### 发出前自检

1. 有没有 ≥ 3 个节点或 table？有就先调 `validate_dsh_ui`，按返回的 next 决定 emit / 修正。
2. 有没有组件字段名写错、`choices` 缺提交按钮、文字里混了 Markdown 表格？
3. 每个章节、每个讲到能看见的东西的要点，后面是不是都紧跟了图？总图数够不够下限？不够就补。
